# FenxTek Shorthand Classes — multi-page site

Static multi-page website with a student portal and an admin CRM. Pages are plain HTML/CSS/JS; Firebase Authentication + Realtime Database provide sign-in and live content.

## Pages

| File | Purpose |
| --- | --- |
| `index.html` | Home (legacy single-page is still `fenxtek-v2.html`) |
| `courses.html` | Courses: dark hero with a live-dictation console, batch grid from RTDB with tag filter chips, "in every batch" bento, fee cards with save %, admission timeline |
| `exams.html` | Exams: category matrix hero, searchable exam explorer (sticky search + category jump chips), speed ladder, exam-day rules |
| `method.html` | Method: daily-loop orbit hero, three detailed steps with mock UI, sample week, illustrative progress chart, why-FenxTek bento |
| `about.html` | About: director portrait hero, director's note (from RTDB), values, testimonials, explore links, contact cards |
| `achievements.html` | Achievements: dark hero with the latest post as a spotlight, ticker, an uncropped photo wall with tag filters, a full-screen reader (zoom, drag, swipe, download, open original) and a "share your result" section |
| `membership.html` | Membership plans (from RTDB), "your membership" banner for signed-in students, FAQ |
| `contact.html` | Join form and contact details |
| `auth.html` | Student sign in / sign up (email + Google) |
| `dashboard.html` | Student portal app: home, My courses + classroom, Course store, course pages, cart with coupons, checkout, orders and PNG receipts, membership, profile |
| `admin.html` | Admin CRM (content, collections, membership plans, student memberships, achievements, students, leads) plus the **Store**: orders & receipts, courses, coupons, payment settings |
| `forgot.html` / `404.html` | Password reset / not-found page |

### Page map — which page reads which RTDB node

`content.js` reads `<body data-page>` and subscribes only to the nodes that page shows (see `PAGE_MAP` in `assets/js/content.js`):

| Page | RTDB nodes |
| --- | --- |
| Home | `site/content`, `site/testimonials`, `site/achievements` (latest 3) |
| Courses | `site/content`, `site/batches`, `site/fees` |
| Membership | `site/content`, `site/memberships`, `site/faqs`, `members/<uid>` (signed-in only) |
| Achievements | `site/content`, `site/achievements`, `site/achievementImages/<id>` (lazy, per picture) |
| Contact | `site/content`, `site/memberships/<id>` when opened as `contact.html?plan=<id>`; writes `site/leads` |
| About | `site/content`, `site/testimonials` |
| Exams, Method, Auth, Forgot, 404 | `site/content` (footer contact details) |
| Dashboard | `users/<uid>`, `members/<uid>`, `site/content`, `site/courses`, `site/courseImages`, `site/offers`, `site/payments`, `carts/<uid>`, `orders/<uid>`, `enrollments/<uid>`, `courseAccess/<id>` (enrolled only), `coupons/<CODE>` (one code at a time, when typed) |
| Admin | everything (admin only) |

Navigation (header, mobile menu, footer) is generated by `chrome.js`, so a new page only needs adding to its `NAV` list.

Shared code lives in `assets/css/site.css` (design system), `assets/css/portal.css` (portal/CRM), and `assets/js/`.

- `chrome.js` injects the sprite, header, mobile menu, footer and page effects.
- `site.js` handles interactions (preloader, reveals, counters, FAQ, join form, footer wordmark).
- `content.js` mirrors RTDB content onto the public pages, using the page map above.
- `media.js` shared helpers: escaping, image URL / base64 validation, the lazy achievement-image loader and the CRM image compressor.
- `auth-ui.js` updates the header “Portal” link after sign-in.
- `firebase.js` loads the Firebase v10 SDK on demand and wraps auth/database helpers.
- `commerce.js` store logic shared by the portal and the CRM: course normalising, coupon checks, cart pricing, order numbers, UPI links.
- `receipt.js` draws the premium receipt on a `<canvas>` (2× resolution) and downloads it as `FenxTek-Receipt-<order no>.png`.
- `dashboard.js` is the student portal. Routes live in one `ROUTES` registry — a new section (live classes, test series, notes…) is one entry plus one view function; the sidebar, mobile tab bar and title pick it up.
- `admin-store.js` is the CRM's Store section (orders, courses, coupons, payments); `store.css` styles the portal and the store screens.

## Firebase setup

### Current project

`assets/js/firebase-config.js` is filled in for the **whatsappy-b69e1** project, and the deployed
Realtime Database rules already match `database.rules.json` (public reads on site content, create-only
leads, admin-only writes).

Still to do in the Firebase console:

1. **Authentication → Sign-in method → Google**: turn it on (Email/Password is already enabled).
2. **Authentication → Settings → Authorized domains**: add `127.0.0.1` if you browse via that address
   (`localhost` is allowed by default, `127.0.0.1` is not) and add your production domain after deploy.
3. Admin owner: `ADMIN_EMAILS` and the rules still use `admin@example.com`. Create an account with that
   address on `auth.html` (Firebase does not require inbox verification), or change both files to a real
   Gmail and republish the rules.

### From scratch

1. Create a project at <https://console.firebase.google.com>.
2. Add a **Web app** and copy the config object.
3. **Authentication → Sign-in method**: enable **Email/Password** and **Google**.
4. **Build → Realtime Database**: create a database (start in locked mode).
5. Paste your values into `assets/js/firebase-config.js`:

```js
export const firebaseConfig = {
  apiKey: "…",
  authDomain: "your-project.firebaseapp.com",
  databaseURL: "https://your-project-default-rtdb.firebaseio.com",
  projectId: "your-project",
  storageBucket: "your-project.appspot.com",
  messagingSenderId: "…",
  appId: "…"
};

export const ADMIN_EMAILS = ["your-admin@gmail.com"];
```

6. Open `database.rules.json` and replace **both** `admin@example.com` references with the same admin email. In the Firebase console go to **Realtime Database → Rules**, paste the file contents and publish.
7. **Authentication → Settings → Authorized domains**: add `localhost` (already default) and your production domain.

> The config values are not secrets; the database rules are what protect the data. Never commit a service-account key.

### Admin access

The first sign-in with the email listed in `ADMIN_EMAILS` self-claims `admins/{uid}` (the rules allow exactly that email to do it). After that the CRM opens from `admin.html`, and the header link changes to **CRM**.

To make another account an admin, open **Realtime Database → Data** and add:

```json
admins
  └── <their-uid>: true
```

To revoke access, set the value to `false` or delete the node.

## Realtime Database shape

```
site
 ├── content        { heroLead, announcement, price, students, dictations, patterns,
 │                    phone, email, telegram, instagram, directorName, directorMessage }
 ├── batches        { <id>: { title, tag, order } }
 ├── fees           { <id>: { label, note, price, was, order } }
 ├── faqs           { <id>: { q, a, order } }
 ├── testimonials   { <id>: { quote, name, exam, badge, order } }
 ├── memberships    { <id>: { name, tagline, price, was, duration, durationDays,
 │                            features: [..], badge, cta, highlight, active, order,
 │                            theme: "" | "ink" | "violet" | "gold" | "pearl" } }
 ├── achievements   { <id>: { caption, title, tag, date, published, order,
 │                            imageSource: "upload" | "link", imageUrl?, width?, height?,
 │                            createdAt, updatedAt, createdBy } }
 ├── achievementImages { <id>: "data:image/jpeg;base64,…" }   ← uploaded pictures only
 ├── leads          { <pushId>: { email, source, at, plan? } }
 ├── courses        { <id>: { title, subtitle, price, mrp, validityDays (0 = lifetime), category, mode,
 │                            language, badge, lessons, features: [..], description, accent,
 │                            published, order } }
 ├── courseImages   { <id>: "data:image/jpeg;base64,…" }   ← optional course covers
 ├── offers         { <CODE>: { code, label, courseIds? } } ← coupons advertised in the portal
 └── payments       { upiEnabled, upiId, payeeName, razorpayEnabled, razorpayKey, businessName,
                      address, gstin, supportPhone, receiptNote }

carts        └── <uid>/<courseId>   addedAt
coupons      └── <CODE>   { code, type: "percent" | "flat", value, courseIds? (empty = all courses),
                            maxUses (0 = unlimited), minAmount, maxDiscount,
                            startsAt, expiresAt, active, batch, note, createdAt }
couponUsage  └── <CODE>   { count, users: { <uid>: <orderId> } }
orders       └── <uid>/<orderId>   { orderNo: "FXT-YYMMDD-XXXXX", uid, name, email, phone,
                            items: { <courseId>: { title, price, mrp, validityDays } },
                            mrpTotal, subtotal, discount, total, coupon?: { code, type, value, discount },
                            status: "paid" | "pending" | "failed" | "refunded", method: "upi" | "razorpay" |
                            "free" | "cash" | "bank", utr?, paymentId?, createdAt, paidAt?, verified? }
enrollments  └── <uid>/<courseId>   { orderId, orderNo, since, until (0 = lifetime), title }
courseAccess └── <courseId>   { message, links: [{ label, url }] }   ← classroom, enrolled students only

members
 └── <uid>          { planId, planName, startAt, endAt, status, paid?, note?, name, email, updatedAt }

users
 └── <uid>          { name, email, phone, exam, speed, createdAt, lastLogin }

admins
 └── <uid>          true
```

- Public read access: `site/content`, `site/batches`, `site/fees`, `site/faqs`, `site/testimonials`,
  `site/memberships`, `site/achievements`, `site/achievementImages`.
- `members/<uid>` is written only by admins; each student can read their own record.
- Achievement pictures are stored separately from the post text so list pages stay light and each
  base64 image is downloaded only when it scrolls into view. The rules cap one picture at ~1.5 MB of
  base64. The CRM keeps them readable: up to ~4.2 MP with a 3600 px long side (tall result lists keep their full width), PNG for screenshots when it fits, JPEG 0.92→0.76 otherwise, always flattened onto white so transparent screenshots don't turn into dark-on-dark text, and capped at ~1.15 MB of base64 (the rules allow < 1.5 MB).
- Public write access: create-only on `site/leads` (email validated by the rules).
- `users/<uid>` is readable/writable by that user; admins can read all students.
- Store: `site/courses`, `site/courseImages`, `site/offers` and `site/payments` are public. Signed-in students
  read and write their own `carts/<uid>`, read their own `orders` / `enrollments`, and can read a single
  `coupons/<CODE>` they type (the coupon list itself is admin-only, so codes can't be harvested).
- The rules check every student checkout: item prices and validity must equal the live course, the total must be
  `subtotal − discount`, the coupon must exist, be active, in date and under its use limit, and `couponUsage`
  must go up by exactly one in the same write. Students can only create three kinds of order: **pending UPI**
  with a UTR, **paid Razorpay** with a `pay_…` id, or **free** (₹0 because of a coupon). Enrolments must point
  at a paid order of theirs and can't run longer than the course validity.
- Everything else requires an admin entry under `admins/`.

## Using the CRM

Open `admin.html` and sign in with the admin account.

- **Overview** — live counts, current price, published announcement.
- **Site content** — hero paragraph, counters, starting price, phone/email/social handles, director details and the student-dashboard announcement.
- **Batches / Fees / FAQs / Testimonials** — add, edit, reorder or remove rows, then **Save**. Public pages re-render from RTDB immediately (no rebuild).
- **Memberships** — **Create plan** adds a plan card to the Membership page (name, price, struck-through price, validity label and days, one feature per line, highlight badge, **card style**, visible on site). Each plan shows as a premium membership card: *Midnight black*, *Royal violet*, *Champagne gold* or *Pearl white*. Leave the style on **Auto** and the highlighted plan becomes the Midnight card with the animated border, while the others cycle violet → gold → pearl. The page works out "Save X%" from the struck-through price and "≈ ₹N a day" from the validity in days, and the hero shows up to three plan cards fanned out, highlighted plan in front. Below that, **Student memberships** activates a plan on a student account: pick the student and plan, and "Valid till" fills in from the plan length. Students see it on their dashboard and the Membership page. The Students tab has an **Assign plan** shortcut too.
- **Achievements** — drag & drop a photo onto the drop zone (or click to browse, or paste with Ctrl/⌘ + V), or switch to **Picture link** and paste an `https://` image URL (Google Drive / Dropbox / GitHub share links are converted to direct picture links; Drive files must be shared as "Anyone with the link"). Add a caption (required), optional title, tag and date, then **Publish post**. Uploaded photos are saved in RTDB as base64; links are saved as-is. Posts can be edited, hidden, reordered with the arrows, or deleted. `admin.html#achievements` opens the tab directly. If the live database blocks anonymous reads, the tab shows a red **Visitors can't see these posts yet** warning (it checks with an unauthenticated REST request), which means `database.rules.json` still needs publishing.
- **Students** — accounts created through the portal.
- **Store → Orders & receipts** — every checkout with revenue stats, search (order no, student, phone, UTR, payment id, coupon) and filters. **Approve** a UPI order once the UTR shows in your bank app — this enrols the student. Razorpay orders show **Verify** until you tick them off against the Razorpay dashboard. View or download any receipt as PNG, reject / refund (removes access), **Record offline sale** for cash or bank transfers, and **Export CSV**.
- **Store → Courses** — create and edit the courses sold in the portal: price, struck-through MRP, validity (or lifetime), category, mode, language, badge, features, description, cover colour or uploaded cover, publish / hide, reorder. **Classroom** sets the message and links (Telegram, YouTube playlist, Drive folder…) that only enrolled students see. **Import from batches** turns the existing batch list into draft courses.
- **Store → Coupons** — a single code or **Bulk generate** up to 500 unique codes per run (run it as often as you like). Each coupon is **percent** (with an optional ₹ cap) or **flat ₹** off, for all courses or particular ones, with optional minimum cart value, total-use limit (0 = unlimited), start and expiry dates. Every student can redeem a code once; set total uses to 1 for single-use codes. Tick **Show as offer** to advertise a code in the portal. Filter by batch, pause or delete a whole batch, and export codes with their usage to CSV.
- **Store → Payment settings** — UPI ID and payee name (the portal shows a QR and an "Open UPI app" button and asks for the UTR), the Razorpay key id, and the business name, address, GSTIN, phone and note printed on receipts. **Preview receipt** draws a sample.
- **Leads** — emails captured by the public “Join now” forms, with CSV export and delete. Leads that came through a plan's **Choose plan** button (`contact.html?plan=<id>`) record which plan.
- **Load starter content** — writes the default website content (from `assets/js/cms-defaults.js`) to RTDB, including one starter membership plan. It never touches achievements, student memberships, students or leads.

> **After pulling this update, republish `database.rules.json`** (Realtime Database → Rules). Until you do,
> the live database denies reads on `site/memberships`, `site/achievements`, `site/achievementImages` and
> `members`, so the Membership page shows its static plan and the Achievements page stays empty — and the
> course store, carts, coupons and orders don't work at all.

> **Payments note.** This is a static site without a server, so a Razorpay payment is recorded with its
> `pay_…` id but isn't verified by a server signature check — that's why Razorpay orders carry a **Verify**
> button in the CRM. For automatic verification, add a small Cloud Function (Razorpay webhook →
> `orders/<uid>/<id>/verified = true`). UPI orders are always manual: the student submits the UTR and you approve.

If a node is missing, the public pages fall back to the HTML that shipped with the site, so a half-filled database never leaves blank sections.

## Deploy (optional)

`firebase.json` is included for Firebase Hosting plus Realtime Database rules.

```powershell
npm install -g firebase-tools
firebase login
firebase use --add        # choose your Firebase project
firebase deploy --only hosting,database
```

Then open the Hosting URL, sign in with the admin account once to claim `admins/{uid}`, and load the starter content from the CRM.
